# Запуск сервера SDonate

Требуется Node.js 20 или новее. Если Node.js ещё не установлен:

1. Открой официальный сайт [nodejs.org](https://nodejs.org/).
2. Скачай вариант **LTS** для Windows и запусти установщик `.msi`, оставив стандартные настройки.
3. После установки закрой и заново открой PowerShell.
4. Проверь установку командой `node -v` — должна появиться версия `v20` или новее.

Не открывай страницы двойным щелчком по HTML: вход и административные проверки работают через сервер.

## Запуск

Из папки проекта запусти:

```powershell
.\start-sdonate.ps1
```

При первом запуске скрипт попросит почту администратора и новый пароль длиной не менее 12 символов. Не используй пароль, который уже отправлял в чат. Сервер сохранит только хеш пароля в `data\users.json`; сам пароль в файл не записывается. При следующих запусках скрипт использует сохранённую учётную запись.

Если PowerShell запрещает запуск скрипта, выполни в этой папке:

```powershell
powershell -ExecutionPolicy Bypass -File .\start-sdonate.ps1
```

После сообщения о запуске открой `http://127.0.0.1:3000/reg.html?mode=login` и войди с введёнными администраторскими данными.

В панели управления можно искать пользователей по нику/почте, смотреть дату регистрации, блокировать и разблокировать обычные аккаунты, а также удалять их после подтверждения. Ссылка на панель отображается в настройках и на главной панели только для аккаунта с ролью администратора и настроенной почтой администратора. Обычный аккаунт доступа не получит. Администраторская запись защищена от изменения и удаления через эту панель. Удаление аккаунта необратимо.

Чтобы открыть управление, войди через сервер и нажми **«Панель управления»** в настройках или открой `http://127.0.0.1:3000/admin.html`. Не открывай HTML двойным щелчком и не используй `file://`: в таком режиме серверная проверка аккаунта и ссылки API недоступны.

Пользователи, хеши паролей и роль администратора сохраняются в `data\users.json`. Держи этот файл в резервной копии с ограниченным доступом. Удаление файла удалит все серверные аккаунты.

## Верификация и уведомления Telegram

Форма в настройках аккаунта сохраняет ФИО и телефон в `data\verifications.json` на этом сервере. Перед отправкой пользователь должен дать согласие. Не собирай документы, если они не нужны для проверки. Доступ к данным заявок есть только у администратора в админ-панели.

Telegram получает только UUID заявки и кнопки «Одобрить»/«Отклонить» — ФИО, телефон и почта туда не отправляются. Для включения уведомлений:

1. Создай бота через официальный `@BotFather` и напиши ему `/start` из своего личного аккаунта.
2. Узнай свой числовой Telegram ID, например через `@userinfobot`. Для защиты решений используются только личные чаты, где ID чата совпадает с ID администратора; группы не поддерживаются.
3. В PowerShell задай переменные в том же окне, из которого запускаешь сервер, и не публикуй токен:

```powershell
$env:SDONATE_TELEGRAM_BOT_TOKEN = "токен-от-BotFather"
$env:SDONATE_TELEGRAM_CHAT_ID = "5171174257"
.\start-sdonate.ps1
```

Если переменные не заданы, заявки всё равно сохраняются и администратор может рассмотреть их в панели вручную. Токен не хранится в проекте. Файл заявок содержит личные данные в обычном JSON-формате, поэтому ограничь доступ к папке `data\` и её резервным копиям.

Локальный HTTP предназначен только для разработки. Для публикации в интернете настрой HTTPS reverse proxy, установи `NODE_ENV=production` и задай `HOST=127.0.0.1`, чтобы Node-сервер был доступен только через proxy с HTTPS. Не запускай его напрямую в публичной сети.

Покупки, управление магазинами на сервере, платежи и расчёт дохода пока не реализованы. В разделе «Серверы» можно добавлять несколько игровых серверов к демо-магазину; эти настройки хранятся только в текущей вкладке браузера. Они не подключаются к Minecraft и не отправляют команды. Не вводи RCON-пароль: безопасный серверный API для него ещё не реализован. В админке показываются зарегистрированные серверные аккаунты; доход остаётся нулевым до интеграции платёжного провайдера.

Оформление в разделе **Магазин → Настройки → Кастомизация** пока является предпросмотром: цвета, тексты и переключатели сохраняются в `sessionStorage` браузера для демо-магазина, а сами фотографии хранятся в IndexedDB отдельно от настроек, чтобы не заполнять лимит `sessionStorage`. Фотографии сжимаются до WEBP (не более 900 КБ; исходный файл до 10 МБ). Публичная публикация витрины и получение реального онлайна ещё не подключены. Четыре картинки магазина в разделе **Картинки** также хранятся в IndexedDB; открой этот раздел и нажми «Сохранить», чтобы перенести ранее загруженные фотографии из старого формата.

Демо-магазины и их настройки в браузере разделяются по ID аккаунта. Это локальная изоляция интерфейса, а не серверное хранилище или граница безопасности: для настоящей работы данные нужно хранить на сервере и проверять владельца каждого магазина в API. Ссылки на соцсети редактируются в разделе **Ссылки** и сохраняются в настройках соответствующего демо-магазина.

Для проверки покупательского вида у магазина есть кнопка **Открыть витрину**. Страница `public-store.html` показывает товары, фото товаров, категории, корзину, оформление, логотип и изображения из раздела **Картинки**, но читает демо-данные из `sessionStorage` и IndexedDB текущей вкладки. Поэтому эта ссылка не является публичным доменом и не откроет магазин на устройстве другого игрока. Доменная маршрутизация, серверная публикация магазинов, платежи и автоматическая выдача покупок не подключены.

В разделе магазина **Страницы** можно добавлять правила и другой Markdown-контент, редактировать его и просматривать результат. Короткий адрес (например, `rules`) создаёт внутреннюю демо-страницу и пункт меню витрины; полный адрес `https://...` добавляет внешнюю ссылку. Внутренние страницы, как и сама витрина, пока доступны только в браузере с сохранёнными демо-данными.

## Плагин SdPlayments

В настройках магазина можно скачать базовый `SdPlayments-0.1.0.jar`. Он предназначен для Bukkit/Spigot/Paper 1.16.5+ и содержит только безопасные команды проверки состояния и тестового сообщения. Приём оплат и выдача покупок не реализованы — плагин нельзя считать платёжной интеграцией.

Для пересборки из `SdPlayments\` требуются JDK 21 и Maven:

```powershell
mvn package
```

Собранный JAR появится в `SdPlayments\target\`. Бета-сборки пока нет.
